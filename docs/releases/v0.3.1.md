Demonstrator · Device Trust Manager v0.3.1: fixes a start failure in v0.3.0. **Update right away if you installed v0.3.0.**

## Install or update

```bash
curl -fsSL https://github.com/danielstroehmann/dc-dtm-demonstrator/releases/latest/download/install.sh | sudo bash
```

Running the installer again updates in place and keeps `.env` and `./data`. It also repairs an installation that v0.3.0 left without a running proxy.

## Fixed

- **v0.3.0 did not start the HTTPS proxy** unless a PKCS#12 file was configured. The start check took the empty placeholder for an unset TLS path for a misconfigured file (`TLS: keystore.p12 is not a file`), so the proxy never came up.
- When the start fails, the installer now shows the TLS check's message instead of an empty proxy log.

## Changed

- Plainer phase names: *Field enrollment* and *Field renewal*. The *One-time setup* steps have their own icon and a neutral grey box next to the blue factory and orange field phases.
- The *Renew* and *Enroll* buttons sit exactly level with their card title; the device table no longer repeats the group name.
- CI now starts the real stack (app, TLS check, proxy) for every commit before an image is published.

## Note for updates from v0.2.0

With the self-signed default, v0.3 replaces Caddy's internal CA with a self-signed certificate created by the installer. A browser that trusted the old certificate warns once again.
