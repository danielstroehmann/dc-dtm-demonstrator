Demonstrator · Device Trust Manager v1.0.0 – the first official release: two new Advanced use cases, among them
real IoT devices running DigiCert TrustEdge with firmware updates over the air, one tile per device, and a login
password set at the first visit.

## Install or update

Ubuntu Server 26.04 (x64 or arm64):

```bash
curl -fsSL https://github.com/danielstroehmann/dc-dtm-demonstrator/releases/latest/download/install.sh | sudo bash
```

Windows 11, Windows Server 2022 or 2025 (x64, Desktop Experience) – in an elevated PowerShell:

```powershell
irm https://github.com/danielstroehmann/dc-dtm-demonstrator/releases/latest/download/install.ps1 | iex
```

Running the installer again updates in place and keeps settings, password and data.

## New

- **TrustEdge managed devices (Advanced license):** each device is an *IoT minion*, a Docker container running
  DigiCert TrustEdge.
  - The factory registers the device in DTM with a serial number and gives it nothing but a one-time passcode.
  - In the field the minion enrolls a long-lived bootstrap certificate via EST (CN = serial number). The TrustEdge
    agent then fetches the operational certificate over MQTT (CN = device name) and renews it itself.
  - **Firmware over the air:** every minion starts with firmware 1.0.0, a dancing figure. Pick a figure and a new
    version with a rolled colour is built, uploaded and released in DTM. Deploy it to the run's devices, before they
    are in the field or while they run. Versions are shared by all runs and reused, because DTM cannot delete
    artifacts and releases.
  - Each tile is a window into its device: installed firmware, the TrustEdge agent's state (online, checking for
    updates, downloading, installing, offline) and a countdown to its next connect.
  - *Add IoT minion* adds further devices to a run, up to 10.
  - Offered for connections to `one.digicert.com`.
  - The installer builds the minion image from DigiCert's public TrustEdge release (pinned version, checksums
    verified). The app reaches Docker only through a socket proxy that allows nothing but containers and images.
- **Retrofit managed devices (Advanced license):** devices that already carry a device-ID certificate from a
  (fictitious) manufacturer's CA enroll a managed certificate in the field with it, via EST or CMPv2. The
  manufacturer's issuing CA becomes the trust anchor of the authentication policy, and the rollback removes it again.
- **One tile per device** for all Advanced use cases: each shows its identity and certificates and has its own
  *Enroll* or *Renew* button. Devices act independently of each other.
- **Login password at the first visit:** the installer no longer asks for a password. Whoever opens the app first
  sets it; it is stored as an Argon2id hash. An `ADMIN_PASSWORD` from an older `.env` is taken over once.
  `install.sh --reset-password` and `install.ps1 -ResetPassword` remove it again and end all sessions.

## Changed

- Use-case tiles explain their use case on hover.
- Managed devices: the run-wide renewal rounds and the *Payload* card are replaced by the device tiles.

## Known limitations

- **TrustEdge managed devices** run on `one.digicert.com` only. On `one.nl.digicert.com` the agent's request for its
  operational certificate is not answered; this is reported to DTM.
- DTM delivers deployments and policy changes when the agent connects. The agent reconnects about every
  two minutes, so an update arrives within that time.
- DTM keeps firmware deployments as *aborted* after a rollback; artifacts and releases are kept and reused.
