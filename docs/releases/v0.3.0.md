Demonstrator · Device Trust Manager v0.3.0: managed devices (Advanced license), a pause for the passcode demo, TLS from `.env`, and a fix for a DTM batch status that reports `failed` too early.

## Install or update

```bash
curl -fsSL https://github.com/danielstroehmann/dc-dtm-demonstrator/releases/latest/download/install.sh | sudo bash
```

Running the installer again updates in place and keeps `.env` and `./data`.

## New

- **Managed devices (Advanced license):** each device is created in DTM (`…-minion-0001`) and its certificate is managed under it.
  - Factory enrollment via REST, EST or CMPv2, authenticated with an API key, a passcode or a factory certificate.
  - Renewal in the field via EST, CMPv2 or REST, chosen independently of the factory protocol (one policy carries both).
  - The certificate's CN is a fictitious serial number or MAC address, mapped to the device by an inventory attribute. After every issuance and renewal the app checks that the certificate sits under the right device.
  - Single device or batch up to 100, renewal per click with statistics. The full rollback removes devices and group as well.
- **Passcode-bound certificates – pause before enrollment:** with *Pause before certificate enrollment* (on by default) the run stops after the passcodes are created, so their configuration can be shown in the DTM portal. *Enroll devices* continues the run. The pause lasts at most 60 minutes, and a rollback ends it.
- **TLS from `.env`:** a PEM pair (`TLS_CERT_FILE`/`TLS_KEY_FILE`, e.g. from Let's Encrypt) or a PKCS#12 file (`TLS_PKCS12_FILE`/`TLS_PKCS12_PASSWORD`). The default is the generated self-signed pair. Every start checks the files and stops with a clear message if they are wrong or do not match.

## Changed

- Official product name: **Demonstrator · Device Trust Manager**, with a matching favicon.
- Every page has the same head (breadcrumb and heading at the same height). Advanced use cases have platinum icons. The start page lists *Recent* runs.

## Fixed

- **Batch jobs:** DTM can report a batch job as `failed` while it is still issuing, and then complete it. The run, the rollback and the exported replay scripts now treat `failed` as final only once it persists. Before, the run stopped while DTM kept issuing certificates. A real failure now logs the job's issued and failed counts.

## Known limitations

- PowerShell snippets are untested on Windows.
- A paused passcode run keeps its passcodes in memory only: restarting the app during the pause interrupts the run (roll it back as usual).
- DTM counts a rejected request against a one-time passcode (reported DTM behaviour).
