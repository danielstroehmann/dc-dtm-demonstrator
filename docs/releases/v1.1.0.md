Demonstrator · Device Trust Manager v1.1.0 – the demonstrator cleans up after itself, shows every device as a
tile with a certificate detail view, updates the run page in place, and takes its own HTTPS certificate in Settings.

## Install or update

Ubuntu Server 26.04 (x64 or arm64):

```bash
curl -fsSL https://github.com/danielstroehmann/dc-dtm-demonstrator/releases/latest/download/install.sh | sudo bash
```

Windows 11, Windows Server 2022 or 2025 (x64, Desktop Experience) – in an elevated PowerShell:

```powershell
irm https://github.com/danielstroehmann/dc-dtm-demonstrator/releases/latest/download/install.ps1 | iex
```

Running the installer again updates in place and keeps settings, password and data.

## New

- **Automatic rollback (watchdog):** a background check every 5 minutes keeps the DTM account clean.
  - Every run is fully rolled back 3 h after it started, using the same full rollback as the button. A run that is
    still busy is rolled back once it is done.
  - If nobody has logged in for 24 h, every run that is not rolled back yet is rolled back.
  - Each run in the overview shows a small clock that fills in quarters until its automatic rollback. The tooltip
    gives the time (UTC).
  - DTM is only called when a rollback is due, and at most one run is rolled back per check. After an update or a
    long downtime, the backlog reaches DTM gradually.
  - A failed automatic rollback is retried later with growing pauses. After 3 failures it stops, and the run's
    timeline asks for a manual rollback.
- **Leftover IoT minions:** minion containers whose run is rolled back or deleted are removed automatically.
  Several demonstrators can share one Docker host: each install labels its own minions and touches no others.
- **HTTPS certificate in Settings:** upload the demonstrator's own certificate – a PEM certificate (with chain) and
  key, or a PKCS#12 file with its password. It is checked (key matches, password, validity), stored on the Docker
  host and applied at once, without a restart. Settings shows the active certificate with its source, names, issuer,
  expiry and SHA-256 fingerprint; **Reset to default** returns to the certificate from `.env` or the self-signed one.
  A PKCS#12 password is never stored.
- **Device tiles for every use case:** one tile per device with its current certificate and its own action button.
  From 11 devices, a compact wall shows all devices at a glance; a click opens the device in a side panel.
- **Certificate detail view:** a click on a tile's certificate opens all of the device's certificates in a picker,
  with CN, SANs, validity, issuer chain up to the root, serial, SHA-256 fingerprint, key usage, extended key usage
  and key type.
- **Enroll all** (passcode-bound device certificates) and **Start all** (TrustEdge managed devices), in addition to
  the button on each device.
- **Run page updates in place:** devices starting, enrolling or renewing update their cards without reloading the
  page – the scroll position and an open side panel stay. Progress lies over the result overview instead of
  pushing the page down.

## Changed

- TrustEdge managed devices run on one.digicert.com only: with a one.nl.digicert.com connection selected, the tile
  is greyed out.
- Each TrustEdge device tile shows its bootstrap and its operational certificate.
- The run page is headed by the use case's name; the runs list shows a running rollback's progress on hover.
- Reproducible steps: values computed on the fly (EST passcode header, firmware upload size) get a line of their
  own before the request.

## Upgrade notes

- Run the installer again (see above). It brings the new compose file with a small volume for the proxy's admin
  socket; the image's group ID is now fixed (10001) so the proxy can read a certificate set in Settings.
- An install without a certificate in Settings keeps serving the certificate from `.env` or the self-signed one,
  as before.
