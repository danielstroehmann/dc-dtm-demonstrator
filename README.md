# Demonstrator · Device Trust Manager

A demonstrator for **DigiCert® Device Trust Manager (DTM)**: it runs typical DTM use cases end to end against
your DTM account, measures them, shows every step as a reproducible API call (curl, wget, PowerShell) and rolls
everything back afterwards with one click.

## Use cases

- **Evergreen device certificates** – long-lived device IDs from the factory: keys generated by DTM or by the
  factory, single device or batch, via the API, the DTM web UI, EST, CMPv2, SCEP or REST.
- **Renewable device certificates** – one device enrolls in the factory and renews in the field per click.
- **Passcode-bound device certificates** – one-time passcodes bound to each device's common name; field
  enrollment via EST or CMPv2, with an optional pause to show the passcodes in DTM first.
- **Managed devices** (Advanced license) – each device is created in DTM and its certificate managed under it;
  factory enrollment and field renewal via REST, EST or CMPv2.

## Install

### Ubuntu Server 26.04

On a fresh machine (minimal installation), as root – one command installs Docker, asks for the initial login
password and the host names for the HTTPS certificate, and starts the demonstrator:

```bash
curl -fsSL https://github.com/danielstroehmann/dc-dtm-demonstrator/releases/latest/download/install.sh | sudo bash
```

Then open one of the printed URLs. Options (`… | sudo bash -s -- <options>`): `--version vX.Y.Z` or
`--branch dev` (development preview), `--host NAME` (repeatable), `--tls-cert … --tls-key …` (own PEM pair),
`--port N`, `--http-port N` (plain HTTP, redirects to HTTPS; default 80), `--yes` (no questions; a password is
generated and shown once), `--uninstall [--purge]`. Running it again updates the installation and keeps data,
password and settings.

### Windows 11, Windows Server 2022 and 2025

As a local administrator, in an elevated PowerShell:

```powershell
irm https://github.com/danielstroehmann/dc-dtm-demonstrator/releases/latest/download/install.ps1 | iex
```

The script enables WSL 2 (a fresh machine restarts once; the installation continues at the next logon of an
administrator, or run the command again), installs WSL from Microsoft's signed package, creates its own WSL
distro `dtm-demonstrator` and runs the Linux installer there. Windows forwards ports 443 and 80 to it, opens them
in the Defender firewall and starts it at boot – no logon needed. Options: `-Version vX.Y.Z`, `-Branch dev`,
`-Yes`, `-Uninstall` – passed as `& ([scriptblock]::Create((irm <URL>))) -Version vX.Y.Z`.

## Configuration

Settings live in `/opt/dtm-demonstrator/.env` (on Windows inside the distro: `wsl -d dtm-demonstrator`), e.g.
`SITE_HOSTS` for the certificate names. After editing it, run `systemctl restart dtm-demonstrator` or reboot.

**TLS** is set in the same file: `TLS_CERT_FILE` and `TLS_KEY_FILE` point to a PEM certificate (with chain) and
key – by default a self-signed pair the installer created in `./tls`; point them to your own files, e.g. from
Let's Encrypt. Alternatively clear both and set `TLS_PKCS12_FILE` and `TLS_PKCS12_PASSWORD` (PEM wins when both
are set). The files are checked at every start; if something is wrong,
`docker compose -p dtm-demonstrator logs tls` says what.

The DTM connection (host, account, API key) is entered in the web UI after the first login.
